# 無駄遣い商会

「あなたのお金を、全力で無駄にする場所」。架空の所持金で無用な商品を購入し、実績と認定証を集める無料のジョークサイトです。実際の決済、請求、配送、個人情報の入力はありません。

## 技術構成

HTML5 / CSS3 / Vanilla JavaScript / localStorage / Canvas API。フレームワーク、ビルド、Node.js、バックエンド、データベース、外部API、外部フォント、広告は使用していません。商品画像・ロゴは本プロジェクトで制作したSVGです。日本語はOSにインストール済みのフォントを使います。

## ローカルでの起動

Windowsでは、このフォルダでPowerShellを開き、次を実行します。追加インストールは不要です。

```powershell
./start-preview.ps1
```

ブラウザで **http://localhost:8080/** を開きます。終了はPowerShellで `Ctrl+C`。8080番が使用中なら `./start-preview.ps1 -Port 8081` で変更できます。実行ポリシーによりスクリプトを実行できない場合は、VS CodeのLive Serverなど、信頼できる静的ファイルサーバーでこのフォルダを開いてください。付属サーバーはループバック接続に限定した開発用で、本番公開には使用しません。

`index.html` のダブルクリックでも基本表示はできますが、`file://` のlocalStorageはブラウザによってページごとに扱いが異なるため、**3ページ間で記録を共有するにはHTTPでの起動を推奨**します。URLのホスト名・ポートを変えると別の保存領域になります。

## 遊び方

1. 初期所持金は架空の10,000円。商品を選び、確認モーダルで架空購入します。
2. 残高を減らし、履歴・累計額・実績・最終利用日時を保存します。同じ品を何度でも購入できます。
3. 成功画面または購入履歴から、認定番号と日付入りの認定証をPNG保存できます。
4. X共有ボタンは共有画面を開くだけです。投稿の確定・PNGの添付は利用者自身が行います。ローカルURLは共有文に含めません。
5. 所持金が不足したら「所持金のみリセット」で10,000円に補充できます。履歴・累計額・実績は維持します。
6. 「データの管理について」の「すべての記録を削除」は、確認後に全記録を削除します。元に戻せません。

保存先はこのブラウザの `muda-shokai:v1` キーです。別の端末・ブラウザとの同期、本人認証、改ざん防止はありません。ブラウザデータの削除やプライベートブラウズの終了で消える場合があります。保存に失敗した場合は警告を表示し、ページ内の一時モードに切り替えます。破損した保存データは自動で上書きせず、全記録削除による復旧を案内します。

## Gitでの管理

既存のGitリポジトリを利用しています。変更は `codex/` で始まる作業ブランチでコミットし、既存の `origin` にpushして保存します。以下は手動で保存する場合の例です。

```powershell
git status
git add .gitignore README.md index.html shop.html achievements.html css js assets start-preview.ps1
git commit -m "Build Muda Shokai static shop"
```

別フォルダへ移す場合は、Git管理されていなければ `git init` で初期化します。秘密情報やAPIキーは不要です。

## GitHubへのアップロード

1. GitHubで空のリポジトリを作成します。ローカルにファイルがあるため、READMEの自動追加はオフにします。
2. 上記のコミットを実行します。
3. `git remote -v` で既存のリモートを確認します。`origin` がない場合だけ次を実行してください。`YOUR_NAME` は自分のアカウントに置き換えます。

```powershell
git remote add origin https://github.com/YOUR_NAME/muda-ec-site.git
git branch --show-current
```

4. 現在のブランチ名を確認し、`BRANCH_NAME` を置き換えてpushします。

```powershell
git push -u origin BRANCH_NAME
```

既存の `origin` がある場合は、そのURLが目的のリポジトリか確認してからpushします。強制pushは不要です。

## 無料ホスティング（GitHub Pages）

GitHub Freeで使う場合は公開リポジトリを利用できます。リポジトリの **Settings → Pages → Build and deployment → Source: Deploy from a branch** を選び、pushしたブランチと **/(root)** を指定して保存します。公開URLはPagesの設定画面に表示されます。ビルドコマンドは不要です。相対パスのためプロジェクト配下のURLでも動作します。

公開前に最新版の[GitHub Pages公式手順](https://docs.github.com/en/pages/quickstart)を確認してください。GitHubへのソース保存とサイト公開は別の操作です。GitHub Pagesの有効化・サイト公開は行っていません。

## 動作確認

- 全JavaScriptの構文チェック
- 初期残高、3商品の購入、履歴・累計・実績の整合性
- 残高不足時の拒否、補充しても累計が残ること、全削除
- リロード相当の再読み込み、保存拒否・破損データ時の退避
- ローカルHTTPで各ページ・CSS・JS・SVGが返ること

実ブラウザでもPC・スマートフォン幅の表示、購入確認→決済中→成功画面、残高・履歴のリロード後の保持、他ページの統計・実績への反映、Escapeによるモーダル終了と購入ボタンへのフォーカス復帰を確認しました。認定証PNGを実際にダウンロードし、日本語表示・金額・日付・認定番号を画像で確認しています。確認ページでJavaScriptの警告・エラーはありませんでした。購入・保存処理は14項目の独立した検証を通過しています。

Xは共有リンクの生成まで確認しています。実際の投稿は行っていません。複数ブラウザ・実機スマートフォンでの互換性、OSの動きを抑える設定は公開前の追加確認を推奨します。

## 拡張方法

商品は `js/storage.js` の `products`、実績は `achievements` が共通定義です。商品追加時はSVGと画像パスを追加し、トップ・ショップの品数表記も更新してください。既存履歴で使用する商品ID・価格を変更すると保存データの検証に影響するため、販売情報と過去履歴の分離を含むデータ移行を設計してください。実績追加時はページ内の総数表記も更新します。

候補：記録のJSON書き出し・復元、商品別コレクション表示、季節限定商品、OGP用の自作画像。全ユーザー統計・ランキング・端末間同期を導入する際は、サーバー側の保存と不正対策、プライバシー設計が必要です。
